# E5-E7 实验计划（修订版）：数据匮乏场景的三条路线 + P0 信号消融

> 动机：E3 的 GRPO 增量小（全集 +1.0pp，难题 12.9→14.5）的根因是「数据少 + 题难
> → 执行奖励稀疏 → 组内全零优势」。本计划验证四条出路：
> **P0 奖励信号消融（过程信号，最便宜）、E5 teacher 轨迹蒸馏（稠密信号）、
> E6 数据自举（正样本回炉）、E7 DPO 偏好对（对比信号）**。
> 基线对照 = E3（全集 33.67%，难题 split 14.52%）。
> 时间窗：2026-09-21 周一 → 周二中午。优先级 P0 > E5 > E6 > E7，跑不完按
> 「完成/设计就绪」如实报告。

## 实测数据更新（2026-09-21 采样/标注完成后）

- **teacher 全量通过率 60.3%**（246/408；试采 83% 是简单题偏向的假绿灯——
  试采分层抽样的价值正体现在这里，全量含难题后回到真实水平）
- **E5 正样本 151 条**（去重后；95 条与参考实现重复被去重——简单题标准答案唯一）
- **teacher 构对仅 ~10 对**：老师的错误大多是「综合就失败」，「综合过仿真错」
  的中间态极少 → **E7 主数据必须是自举对**（学生自己的中间态错误丰富），
  teacher 对降级为补充数据——这本身是「DPO 负样本要贴近学生错误分布」的
  数据侧证据

## 修订记录（2026-09-21）

1. **P0 新增**：奖励开关消融（split_reward/lint），与 E5 试采并行，零机会成本
2. **E5 采样池修正（防泄露）**：148 题 → 严格 102 训练题（62 V2 train + 40 自建
   train）；评估题（36 V2 eval + 14 自建 eval）一个字都不能进训练
3. **E5 teacher 试采前置**：先 30 题 × n=2 测 DeepSeek 双闸通过率，达标才全量
4. **E6 增益预期下调**：正样本率 30-40% → 25-35%（训练题难题占比高），去重后
   预计 150-250 条；预期增量 +1~3pp
5. **过采样方案否决**：难题 2× 过采样不移出设计（132 步过拟合证据：过采样把
   难题提前推进过拟合区；且难题已占训练池 66%，边际信号小）——难题数据修复
   只走「扩池」路线（P1 新难题，本次不排）
6. **调研修订（2026-09-21 晚，见 docs/调研-方法论文档.md）**：
   - P0 补 **P0b**：n=8 + split_reward + DAPO 组过滤（filter_groups）——调研

     组大小主效应
   - **E6 升主路线、E5 降补充**：on-policy 蒸馏（学生自采 + 执行过滤）优于
     teacher 自采 off-policy SFT——E6 优先，E5 数据照收作对照
   - 顺序不变：SFT → DPO → GRPO 与规范一致

## 路线组合关系（2026-09-21 三次修订：canonical 训练顺序）

**原则：SFT → DPO → GRPO，RL 收尾**（先 GRPO 后 SFT 会拉回分布/遗忘/
冲掉奖励塑造——2026-09-21 用户指正）。三个轴各自消融，最终模型 =
三个轴胜者的顺序组装：

```
基座 ──→ SFT（数据源轴）──→ DPO（对比轴）──→ GRPO（配方轴）──→ 最终模型
          E2 参考实现 32.7%    E7a 自举对        P0a split_reward
          E5 teacher 蒸馏      E7b teacher 对     E3 二值（基线）
          E6 自举
          E5+6 三源混合
```

- 每个轴的实验**同起点、唯一变量**（数据源轴从基座起；DPO 轴从组合 SFT 起；
  配方轴从 e2-sft-merged 起）
- 数据就绪即可并行：E5/E6 的 SFT 可同时跑，不串行
- 最终模型组装顺序固定：胜者数据 SFT → 胜者 DPO → 胜者 GRPO，不交换
- 报告口径：三个轴各报单变量增量，最终模型报组合增量
- E7 构对规则（仿真过 > 综合过仿真错 > 综合失败）与 split_reward 三档思想
  同构——DPO 轴与配方轴有机制呼应，可交叉引用解释

## P0：奖励信号消融（2 个实验，~¥12，2 小时）

**假说**：难题组内 n=4 样本全错 → advantage 方差为零 → RL 无方向。给综合过
的样本 +0.3 过程信号，组内就有分化（综合过 vs 没综合过），GRPO 重新有梯度。

| 实验 | split_reward（综合+0.3/仿真+0.7） | lint_bonus（±0.2） | 回答的问题 |
|---|---|---|---|
| E3（已有基线） | ✗ | ✗ | 全集 33.67% / 难题 14.52% |
| **P0a** | ✓ | ✗ | 过程信号有增量吗——**主实验** |
| P0d | ✓ | ✓ | lint 的条件增量（先验：预期 ~0，权重太小 + 警告是功能弱代理） |

**控制变量**（口径纪律）：e2-sft-merged 同一起点、66 步（E3 最优停止点）、
同 seed、同评估命令、reward_fn 仅改对应开关。**判据三层**（n=98 时全集
95% CI ≈ ±9.4pp，单点对比不可靠）：
1. 机制判据（最硬）：**组内优势方差**——split_reward 的设计目的就是提高组内
   信号分化，从训练日志统计每组 score std，P0a 应显著高于 E3（方差不涨而
   分数涨 = 归因存疑；方差涨分数不涨 = 机制对但强度不够）
2. 分层一致性：难题 split 增量 ≥ +3 题（~+5pp）才算有效
3. 失败原因迁移：综合过样本的 advantage 应分化（reward 分布统计）

**序贯策略**：先跑 P0a；有效再跑 P0d 测 lint 条件增量；P0a 无效则 P0d 也省了。
诚实纪律：P0a 无增益 = 「组内方差假说证伪」，照实写进结论。

## 起点选择逻辑（2026-09-21 二次修订）

**主轴（数据源对照）：全部从基座起**——E2（参考实现）vs E5（teacher 蒸馏）
vs E6（自举）三路同起点、同 SFT 框架、同超参，唯一变量 = 数据来源。这是
JD 第 1 条「数据工程」的核心对照：不同来源的 spec→RTL 数据各自值多少。
三路数据就绪后可并行训练，不串行。混合数据（参考+teacher+自举）单独一格，
测数据源互补性。

**副轴（RL 配方）：从 e2-sft-merged 起**——P0a（split_reward）vs E3（二值）
测的是「奖励配方」，起点必须是 GRPO 之前的最优（E2），从 E3 起会掺入
「已训练 66 步」的变量。两个轴正交，各自报告增量。

**DPO（E7）：从组合 SFT 模型起**——DPO 需要 SFT 过的模型（reference model
语义），从基座直接 DPO 无意义；构对来源对比（自举对 vs teacher 对）在
E7a/E7b 内做。

| 实验 | 起点 | 理由 |
|---|---|---|
| E2（已有） | 基座 | 参考实现数据（对照腿） |
| E5 | **基座** | teacher 蒸馏数据——与 E2 同起点，唯一变量 = 数据源 |
| E6 | **基座** | 自举数据（采样自 P0 胜者，但 SFT 从基座训）——三路对比的第三腿 |
| E5+6 | **基座** | 三源混合——测互补性 |
| P0a | e2-sft-merged | RL 配方轴，起点 = GRPO 前最优 |
| E7a/E7b | 组合 SFT 模型 | DPO 需要 SFT 起点；两格唯一差异 = 构对来源 |

一句话：**数据源轴从基座起（同起点比源），配方轴从 E2 起（同起点比配方），
DPO 从组合模型起（框架语义要求）。**

## E5 详细设计（teacher 轨迹蒸馏）

1. **试采（前置，本地电脑，几毛钱）**：deepseek-chat 对 30 题（分层抽：15 难题
   + 15 自建）× n=2 生成，双闸标注 → teacher 通过率。**通过率 < 40% 则 E5 降级**
   （teacher 天花板太低，蒸馏无意义——转 E6 自举路线）
2. **全量采样**：102 训练题（62 V2 train + 40 自建 train）× n=4（temperature 0.7）
   → ~400 条轨迹；**采样池严格排除评估题（36+14）——防泄露红线**；提示词要求
   `<answer>` 内完整 module（与训练格式对齐）；Search-R1 的 API 蒸馏管线
   （397 条轨迹）复用脚本模式
3. **过滤**：双闸标注；「综合过 + 仿真过」为 SFT 正样本；「综合过仿真错」留作
   E7 负样本
4. **SFT**：LLaMA-Factory + LoRA（同 E2 配置），**训练 E2 基线模型**（不是从基座）
   ——teacher 数据补 E2 没见过的分布
5. **评估**：同口径全集 98 + 自建扩展集 50
6. **口径**：结论文档写清 teacher = DeepSeek API（deepseek-chat）；工业界用 API
   强模型当 teacher 是常态，与 Search-R1 同一条管线

## E6 详细设计（数据自举）

1. **采样**：当前最优模型（P0a 或 E3）对 102 训练题采样 n=8 → ~800 条
2. **过滤**：双闸标注；「综合+仿真全过」为正样本（预期 25-35% → 200-280 条，
   **去重后 150-250 条**——贪心采样同题高度重复，去重是必须步骤）
3. **回炉**：正样本并入 SFT 数据（去重）→ 对最优模型做一轮 SFT（低 LR，1 epoch）
4. **假设**：模型在自己最强样本上再学一轮 → 分布内强化，+1~3pp（预期已下调）

## E7 详细设计（DPO 偏好对）

1. **构对规则**（同一 spec 内配对）：chosen = 仿真通过的轨迹（多个取最先/最短）；
   rejected = 综合过但仿真错的轨迹；无仿真通过样本的题跳过
2. **数据规模**：预计 80-150 对（难题多「综合过仿真错」样本，构对数据充足）
3. **训练**：LLaMA-Factory DPO 配置，基于 E6 后模型；新工具路径，踩坑时间计入
4. **假设**：学「好 vs 坏」的对比比学绝对奖励更省数据，+1~3pp

## 评估口径（与 E1-E3 完全一致）

- 同一 eval_rtl.py、同一采样（贪心 n=1）、pass@1
- 双口径：VerilogEval V2 全集 98 题（官方口径）+ 自建 50 题扩展集
