## 一、项目是什么

**任务**：训练 Qwen2.5-Coder-3B 模型生成 Verilog 硬件描述代码。输入一句自然语言
规格（如「写一个 8 位计数器，带同步复位和使能」），输出完整可综合的电路模块。

**判对错的方式（核心特色）**：自建「双闸」判定——
1. **Yosys 综合**：检查语法与可综合性（等价于软件代码的「编译通过」）
2. **Verilator 仿真**：把电路真实跑起来，逐拍喂输入、比对输出（等价于
   「单元测试通过」）
3. 两道闸都过才算对。该判定既用于训练奖励（GRPO 的奖励信号），也用于评估
   （与训练同一套代码，不存在口径漂移）。

**为什么要做这个**：RTL 域天然有客观可验证信号（综合+仿真），是强化学习
可验证奖励（RLVR）的理想场景。项目是把在软件代码上验证过的方法论
（SFT 教语法、RL 教功能）平移到硬件域的 mini 复现（对标 2025 年论文 VeriRL）。

**资源**：单卡 A800-80G GPU，veRL 强化学习框架，总花费约 ¥50。

## 二、完整流程（五阶段，M1→M5）

```
M1 参考数据 SFT 冷启动
    ↓
M2 双闸奖励 GRPO（含三组配方对照）
    ↓
M3 DeepSeek 蒸馏 + 模型自举扩数据，再 SFT
    ↓
M4 双闸标注轨迹构对 DPO
    ↓
M5 双闸奖励 GRPO 收尾
```

- M1：用 102 条（自建 40 + VerilogEval 62）规格-参考实现对训练，LoRA 微调
- M2：用双闸结果当奖励跑 GRPO；期间做了三组奖励配方对照（详见第四节）
- M3：数据扩展——DeepSeek API 当老师采样 408 条轨迹、M2 模型自采样 816 条，
  全部双闸标注过滤，得到 289 条功能验证新数据，三源合并（391 条）再 SFT
- M4：把双闸标注的轨迹构造成「好答案 vs 坏答案」偏好对（26 对），DPO 训练
- M5：在 M4 模型上用双闸奖励 GRPO 收尾（采用 M2 对照中胜出的配方）

## 三、数据工作（详细过程）

### 3.1 自建数据集：54 题 spec→RTL
- 覆盖组合逻辑 20 题 / 时序逻辑 20 题 / 状态机 14 题，三档难度
- 每题含：自然语言规格、接口契约（module 声明）、参考实现、测试向量
- **数据诚信底线**：每道题的参考实现必须先通过自己的双闸校验（综合+仿真
  全过）才入库——数据集本身先自证正确

### 3.2 VerilogEval V2 清洗
- 下载官方 156 题，清洗保留 98 题
- 剔除原因（如实报告）：46 题参考实现过不了综合（含 SystemVerilog 特性）、
  11 题端口位宽超 64（自建评测框架上限）、1 题重复
- 这个「可综合性过滤」本身就是数据工程动作

### 3.3 DeepSeek 教师蒸馏（M3 一部分）
- DeepSeek API 对 102 道训练题各采样 4 条，共 408 条轨迹（花费约 ¥3）
- 双闸标注：通过率 60.3%
- 过滤出「仿真全过」的 151 条作为新训练数据（去重后）

### 3.4 模型自举（M3 另一部分）
- 用 M2 模型对 102 道训练题各采样 8 条，共 816 条轨迹
- 双闸标注：通过率 35.8%
- 过滤出 138 条「仿真全过」的新数据（去重后）
- 这相当于让模型自己生成候选、用双闸自动验证、把成功的回炉——零人工标注

### 3.5 DPO 偏好对（M4 的数据）
- 来源：双闸标注的全部轨迹
- 构对规则（同一道题内）：好的 = 仿真全过的轨迹；坏的 = 综合过但仿真错的
  轨迹；两类都有才构对
- 得到 26 对（自举对 16 + 教师对 10）——数量偏少是如实报告的局限

## 四、配方对照实验（M2 期间，三组单变量对照）

每组只改一个变量，其余配置与基线完全一致（同一模型起点、同样 66 步）：

| 对照 | 改动 | 结果 | 结论 |
|---|---|---|---|
| 奖励拆分 | 综合 +0.3 / 仿真 +0.7 两段奖励 | 全面退化（FSM 档 -19pp） | **弃用**：二值奖励（对=1、错=0）更优 |
| 组采样 | 每组采样数 4→8，并过滤全对/全错的无信号组 | 难题通过率 +5.2pp | **采用**：定为收尾配方 |
| 训练长度 | 66 步 vs 132 步 | 132 步训练奖励继续涨但泛化下降 | **66 步为最优停止点** |

## 五、数字库（全部口径，含归因）

### 5.1 最终效果（基线 → 最终模型）

| 指标 | 基线（零样本） | 最终模型 | Δ |
|---|---|---|---|
| VerilogEval V2 全集（98 题） | 20.4% | 50.0% | +29.6 |
| 其中难题（62 题） | 9.7% | 41.0% | +31.3 |
| 未见题（50 题，从未进训练） | 34.0% | 60.0%（M2 阶段达到） | +26.0 |

### 5.2 各阶段增量（归因）

| 环节 | 数字 | 归因说明 |
|---|---|---|
| SFT 冷启动（M1） | 全集 20.4→32.7 | 教语法与简单题 |
| GRPO（M2） | 未见题 56.0→60.0 | 教功能（状态机 0→2/6） |
| 数据扩展再 SFT（M3） | 难题 12.9→21.3 | 三源混合数据 |
| DPO（M4） | 未见题无增量（分布内 +1.3pp） | 26 对偏少 |
| GRPO 收尾（M5） | 全集 37.8→50.0 | 训练分布内大幅提升 |

### 5.3 核心发现（最有价值的结论）

**小数据下「分布内提升」与「泛化」脱钩**：把训练数据做厚、管线做长，模型在
训练过的题上大幅进步（全集 20.4→50.0），但在从未见过的题上，泛化最好的
是最简管线（SFT+GRPO，60.0%），后续每一步扩张都是分布内强化、泛化中性或
略负。这个发现来自项目自建的「未见题口径」——把从未进过训练的 50 道题
单独作为评测集，防止把训练集成绩误报成模型能力。

## 六、口径红线（简历写作必读，防止数字用错）

1. **50.0% 和 41.0% 是「全集/难题」口径**，包含 62 道模型训练过的题。
   写简历时必须注明口径，或只写「未见题」口径的数字（60.0%）。
2. **60.0%（未见题）是 M2 阶段达到的最好泛化成绩**；最终模型（M5）在
   未见题上是 54.9%。若简历写「最终模型」的数字，用 50.0/41.0（标注全集
   口径）或 54.9（未见口径）。
3. **+5.2pp（难题）** 来自「组采样 4→8 + 过滤全对全错组」的配方对照，
   不是数据扩展的功劳。
4. **DPO 的结果**：未见题零增量、训练分布内 +1.3pp——如实写「小样本下
   效果有限」，不要写成「DPO 提升 X」。
5. 所有数字的原始出处：`results/*/report.json`，可对账。

## 七、工程产出（可写进简历的工程能力）

- **自建双闸评估基准**：自动生成 Verilator C++ 测试 harness，逐拍驱动输入、
  比对输出；没有测试向量的题目用参考实现当「判官」（同输入逐拍比对输出）；
  按难度分层报告（简单/难题/状态机分开报）。
- **veRL 集成**：自定义奖励函数（双闸调用、结果缓存、并发、超时杀进程组）、
  DAPO 组过滤配置、checkpoint 轮转守护（防磁盘爆）、训练崩溃自动关机守护。
- **全程踩坑记录**（work-log 系列）：veRL 数据格式契约（reward_model dict 化、
  prompt 消息列表化）、磁盘三次写满的预防机制、双进程写坏数据的教训、
  CRLF 陷阱——每个坑都有复现、定位、修复、防复发断言四件套。
