# 调研：数据匮乏代码 RL 的方法论规范（2026-09-21）

> 目的：回答三个问题——① 训练顺序 SFT/DPO/GRPO 怎么排；② 组内零梯度
> （难题全错组）的规范解法；③ 蒸馏/自举/DPO 三条数据路线哪个是主路线。

## 一、训练顺序：SFT → DPO → GRPO（RL 收尾）

- Post-training 栈每阶段解决不同问题：SFT 教格式/指令跟随（「能用几百条
  标注教的事，不要用 RL」）；DPO 对齐「什么输出可接受」；GRPO/RLVR 在
  对齐空间内把能力推到数据之外
- **「DPO for taste, GRPO for reasoning」**——顺序错了或目标混了是常见错误
- 跳过 DPO 的常见生产顺序 = SFT → GRPO 直接（MIP、NVIDIA Nemotron Super 3、
  GLM-5 皆如此）
- **对 E5-E7 的裁决**：用户「先 SFT/DPO 再 GRPO」的直觉正确；我们的三轴
  组装顺序（数据源 SFT → DPO → GRPO）与规范一致 ✓
- 关键闸门：**RL 前模型必须已能偶尔成功**（RL 磨利已有能力，不无中生有）——
  E3 的 FSM 0→33% 之所以成立，是因为 SFT 已给模型 Verilog 能力底座

## 二、组内零梯度：DAPO Dynamic Sampling + 组大小

- 难题组 n=4 全错 → std=0 → 每 token 优势为 0，且这些 token 留在 loss 分母
  里稀释梯度——这正是我们 E3 难题增量小的机制，DAPO 论文点名的退化组问题
- **DAPO 解法**：Dynamic Sampling 强制 0 < 正确数 < G，丢弃全对/全错组，
  保证每批都有混合信号
- **组大小**：DAPO 消融 code 任务收益到 N=16 饱和；受控复现 GSM8K 组大小
  {4,8,16,32}：67.2 / 71.4 / 74.8 / 75.9（N=4→8 +4.2pp 显著，N=8 仍是
  曲线中段偏低）——**我们 n=4 明显偏小，n=8 是底线不是建议**
- veRL 内置 `algorithm.filter_groups.enable`（DAPO 式组过滤）——实例 verl
  版本需验证是否可用

## 三、数据路线：on-policy 蒸馏 > off-policy SFT

- **Rejection sampling**（best-of-N → SFT 赢家）被描述为「没有 RL 回路的
  快速增益」= 我们的 E6 自举
- **On-policy distillation**（强 teacher 给学生**自己的** rollout 打分，
  逐 token 稠密）「在该场景优于 SFT 和 GRPO，且恢复 SFT 丢失的泛化」——
  推荐在任何 RL 回路前使用
- 我们的 E6 = on-policy 蒸馏的双闸版（双闸 = 客观 teacher 对学生 rollout
  打分）——**调研把 E6 抬到主路线地位**；E5（teacher 自采 off-policy SFT）
  是传统蒸馏，优先级应低于 E6
- 反直觉但重要：teacher 自采数据的价值 < 学生自采 + 执行过滤的价值——
  我们已实测印证（teacher 全量通过率 60.3% 且构对仅 ~10 对；学生中间态
  错误才是丰富信号）

## 四、其他直接可用的配方要点（2025 收敛配方）

- 格式奖励 + 正确奖励的复合：「格式对但答案错」与「格式错」**不应同分**——
  split_reward 思想被背书 ✓
- lr 5e-7 / beta(KL) 0.01 / n=8 是收敛起点（我们 lr 1e-6 / kl 0.001 偏保守，
  可向收敛点调）
- Prompt curation：选题要在模型的「难度带」内（全对/全错组都零梯度）

## 五、对计划的修订（写入 E5-E7 计划）

1. **P0 补一格 P0b**：n=8 + split_reward + 组过滤（verl filter_groups 若可用）
   ——把调研背书的三个改动打包，与 P0a（n=4）对比组大小主效应
2. **E6 升主路线、E5 降补充**：先跑 E6（自举+回炉，on-policy 蒸馏等价物），
   E5（teacher 数据）作为数据源对照保留但优先级后移
3. **顺序不变**：三轴组装 SFT → DPO → GRPO ✓
