# RTL-RLVR 项目设计文档（完整版 · 小米 JD 定向）

> 一句话：用「Yosys 综合 + Verilator 仿真」当天然可验证奖励，在 RTL 域复现 RLVR 管线——VeriRL 的 mini 复现，嫁接 Code-R1 方法论骨架 + Search-R1 稳定性工具 + 前两个项目的全部工程经验。

---

## 〇、任务是什么（零基础版：也写代码，写的是硬件）

**任务 = 代码生成**，和 Code-R1「题目 → Python」完全同构，只是目标语言换成 Verilog（硬件描述语言）：

```
输入 spec（自然语言规格）：
"Write an 8-bit counter that increments by 1 each clock cycle,
 with a synchronous reset."

模型输出（Verilog module）：
module counter (
    input  wire clk, input  wire rst,
    output reg  [7:0] count
);
    always @(posedge clk) begin
        if (rst) count <= 8'd0;
        else     count <= count + 1;
    end
endmodule

判分（RTL 版「沙箱」，两道闸门）：
① Yosys 综合：语法对不对、能不能变成电路（≈ 编译通过）
② Verilator 仿真：喂时钟和复位信号真实运行电路，逐周期检查输出（≈ 跑测试用例）
③ 两闸全过 = 这道题对
```

**与 Code-R1 的逐项对应**（面试金句：「我在代码项目里做的所有事，换了个语言重做一遍」）：

| Code-R1 | RTL-RLVR |
|---|---|
| 题目 → Python 代码 | spec → Verilog module |
| 编译（ast.parse） | Yosys 综合 |
| 沙箱跑测试 | Verilator 仿真 |
| 执行奖励 = 格式 0.1 + 正确 1.0 | 同构（module 解析 + 双闸全过） |
| 1.5B verifier 预测 k/N | RTL verifier 预测综合+仿真通过率（可选） |
| 门控蒸馏 | RTL 蒸馏门控（可选） |
| 异常轨迹过滤 | 综合失败/超长/空 module 剔除 |

## 一、项目概述与目标

- **目标 1（面试证据）**：跑出 E1-E3 对比数据——「SFT 学格式、RL 学功能」在 RTL 域复现，证明方法论跨语言可平移
- **目标 2（JD 对齐）**：SFT 用 LLaMA-Factory、GRPO 用 veRL、评估脚本自建——JD 第 2、3、4 条全部有真数据
- **目标 3（叙事）**：RTL 的奖励比软件代码更干净（仿真无运行时不确定性）——RLVR 的完美落地场景

## 二、数据设计（JD 第 1 条）

**数据源**：VerilogEval 训练集（143 题）+ 公开 Verilog 语料（RTLCoder 用过的 OpenRTL 类）取子集 500-1000 条。

**数据格式（统一 spec→RTL 对齐）**：
```
{
  "spec": "Write an 8-bit counter...",     # 自然语言规格
  "module": "module counter(...)...",       # 参考实现（SFT 用）
  "tests": [{ "input": {...}, "expect": {...} }]  # 测试向量（仿真判分用）
}
```

**清洗规范**：过滤非 Verilog / 截断 / 重复；spec 与 module 必须成对；按难度分桶（组合逻辑 / 时序逻辑 / 状态机）。

**自动标注（零人工）**：每条候选实现跑双闸 → 标注「综合过/不过 + 仿真 k/N」——Code-R1 沙箱标注的 RTL 版。

**DPO 偏好对（可选阶段）**：同一 spec 两个候选实现按「仿真通过 > 综合通过 > 失败」排序构对；优先保留「综合过但仿真错」的负样本（更有教学价值）。

## 三、训练设计（JD 第 2 条）

### 阶段 1：SFT（LLaMA-Factory）
- 基座 **Qwen2.5-Coder-3B-Instruct**（JD 点名），LoRA（rank 32 / alpha 64，复用你的 SFT 路线）
- 数据：清洗后 Verilog 子集；损失 = 负对数似然
- 目的：学 Verilog 语法与 module 格式习惯；产出 SFT 基线 + 格式成功率

### 阶段 2：GRPO（veRL）
- 复用 Code-R1 的 veRL 配置（组大小 4、KL 0.001、学习率 1e-6），**只改 reward_fn**：

```
总奖励 = 格式 + 正确性（满分 1.1，与 Code-R1 同构）
  格式：<answer> 内解析出完整 module（+0.1）；解析失败（-0.1）
  正确性：Yosys 综合失败 → 0
          综合通过 + Verilator 仿真全测试通过 → 1.0
          综合通过 + 部分通过 → 0（保持二进制，与方法论平移叙事一致）
```

- **加分设计一：综合与仿真拆两段奖励**（综合 +0.3 过程信号、仿真 +0.7 结果信号）——客观执行产生的过程信号，不会重蹈手写 PRM 被黑客的覆辙
- **加分设计二：行为级过程奖励（lint 方案，可选开关，默认关）**——`verilator --lint-only -Wall` 输出映射为行为奖励：BLKSEQ（时序块阻塞赋值）−0.05 / BLKANDNBLK（混用赋值）−0.05 / WIDTH（位宽不匹配）−0.03 / UNDRIVEN（未驱动）−0.05 / COMBDLY −0.05 / CASEOVERLAP −0.05 / 零警告 +0.1，封顶 ±0.2。规则由工具定义（行业标准），不是手写拍脑袋；配合少量静态格式规则（module 配对、端口方向、注释）共 ≤10 条。**验证纪律（吸收 22 条教训）**：触发率统计 + 开关消融写进实验计划，默认关闭、E 系列里单独验证
- **防钻空子**（答案现成）：主奖励是客观仿真钻不了；格式坏负分；异常过滤三类（综合反复失败、输出超长/解析失败、空 module）剔除后组内重算优势

### 阶段 3（可选）：RTL verifier + 门控
- 用仿真标注数据训 1.5B verifier（预测综合+仿真通过率）；用法 ×0.1 软信号或门控蒸馏——Code-R1 方法原样搬

## 四、评估规范（JD 第 3 条）

- **数据**：VerilogEval 机器评估集子集（30-50 题）+ 自建 10 题 spec 集（组合/时序/状态机分档）
- **双闸判定**：Yosys 综合 → Verilator 仿真，两闸全过才算对
- **分层指标**（RTL 特有洞察）：pass@1 总通过率 / **综合通过率** / **仿真通过率**分开报——能定位模型是「语法没学会」还是「逻辑没学会」
- **口径纪律**：所有模型同一脚本、同一次采样、pass@1（继承六模型评估的老规矩）

## 五、实验矩阵（JD 第 4 条）

| 实验 | 配方 | 预期结论 |
|---|---|---|
| E1 | 基座 zero-shot | 基线（可能极低——反而强化「SFT 教格式」的对比） |

## 七、操作手册（前两项目的实战经验）

1. **租卡（AutoDL）**：先无卡模式（¥0.1/h）开机传数据、装环境；环境就绪再切 GPU 卡；训练完及时关机省钱；实例上数据盘持久化，下次直接续
2. **模型下载**：Qwen2.5-Coder-3B-Instruct 约 7GB——**用 ModelScope 镜像下载**（国内快，避免 HuggingFace 直连超时；前项目用过 HF 上传 wang072266/qwen3.5-4b-search-r1-sft，下载端改用 ModelScope 更稳）
3. **环境部署**：veRL 环境已在 Code-R1 实例上配好（配置和 PITFALLS 手册都在）——直接复用该实例或按手册重建；**红线：不装 flashinfer（会降级 torch）；沙箱/仿真执行用自制脚本**
4. **工具安装**：Yosys + Verilator 用 `apt install yosys verilator` 一条命令（AutoDL 镜像自带 apt 源）
5. **网络**：GitHub push 走代理 127.0.0.1:7897（老问题）
6. **版本对齐**：veRL main 分支 API 漂移历史问题——锁 commit 跑实验（E6B API 漂移的教训）

## 八、规范（先定口径再动笔）

1. **口径纪律**：所有跑分同一脚本、同一次采样、pass@1；基线（E1）最先跑
2. **诚实纪律**：负面结果保留并如实报告（手写 PRM 失败、门控无增量的先例）；结论作废要显式标注（verifier 链路 bug 的教训）
3. **可复现纪律**：配置断言 dry-run（config_dryrun 的做法）；每个实验存完整 config + 日志
4. **开源纪律**：结论文档 + 教程 + 踩坑手册（两个老项目的 GitHub 习惯）

## 十一、风险与降级

1. **VerilogEval 数据获取**：官方仓库开源；受限则手工构造 50 题 spec 集（规格 + 参考实现 + 测试向量，半天工作量）
2. **模型不会写 Verilog**：E1 基线可能极低——不影响叙事，反而强化 SFT/RL 分工对比
3. **综合/仿真环境**：apt 一条命令；AutoDL 实例自带
4. **时间不够**：保底交付 = 评估脚本 + E1/E2 对比（SFT 前后），GRPO 数据后补
